## 核心功能

### 1. 我的進度 - 選成員看所有紀錄
- 頂部「檢視成員」下拉選任何人，查看其完整進度（包括其他獎章）
- 直接勾選 + 輸入日期（剔即填今日，可手改日期）
- 級聯自動完成：勾上層自動勾所有下層
- 離線暫存 → 底部 SaveBar 顯示數量 → 按確認才批量寫入雲端，有進度提示

### 2. 全團總覽 - 一眼睇 + 批量剔
- **卡片總覽**：每人完成度% + 四個獎章百分比，一眼睇邊個完成會員章（顯示會員章✓標籤）
- **表格矩陣**：按段章篩選，最多30欄防卡死，點✓可單獨切換
- **🚀考驗營批量完成**：例如剛去完考驗營
  - 選日期
  - 左選有去的成員（支援搜尋過濾，全選/取消全選）
  - 右選本次考驗的項目（支援全選）
  - 一鍵標記 → 暫存 → 確認寫入，唔使逐個跳轉
- **按成員/按項目統計**：子切換按鈕，一個分頁內完成（手機省闊度）

### 3. 待批 - 成員申請
- 成員「申請完成」後在此顯示，含日期、證據
- 可單個批准/拒絕，或批量選中批准
- 批准後自動加入待寫入清單

### 4. 📅 活動履歷 - 服務／活動／訓練班紀錄（v8.2）
- 記錄成員參加的各項活動：**🤝 服務紀錄**（名稱、崗位、時數，自動統計總時數）、**🏕️ 活動紀錄**（露營、比賽、參觀等）、**🎓 訓練班紀錄**（班名、身份、時數、證書編號）
- 「檢視成員」可切換任何成員；**成員亦自行申報自己的紀錄 → 領袖審批後才寫入**
- **➕ 新增紀錄**（領袖）：選類型 → 成員 → 日期 → 名稱 →（崗位／時數／證書編號按類型顯示）→ 儲存
- **📥 批量補登**：新增時勾「批量：同一活動套用到多個成員」，例如全團露營一次過幫 20 人建立（單次最多 200 筆）
- ✏️ 編輯／🗑️ 刪除：紀錄右側按鈕（刪除會先確認，且寫入操作紀錄可追查）
- **📅 履歷審批**（「✅審批中心」內）：成員申報／申請修改的活動履歷在此審批。批准後自動寫入「活動履歷」；修改類批准後會更新原有紀錄
- 權限：領袖可直接寫入／編輯／刪除（需角色含勾選權且「授權勾選」開啟）；成員只能申報自己的紀錄（新申報或修改已批紀錄，均需領袖審批）；其他（進度勾選、其他獎章）批准後成員不能自行修改，只有領袖可改
- ⚠️ 如顯示「後端尚未升級 v8.2」： Apps Script 貼上最新 Code.gs → 部署 → 管理部署 → 編輯 → 版本選「新版本」→ 部署 → 喺試算表選單按「🔗 旅系統 → 🔧 初始化／更新」補建「活動履歷」及「待批履歷」工作表（只補缺失，唔會刪改現有資料）

### 5. 表格列印 - 官方格式
- 自動填入姓名、YMIS、旅團、各項完成日期
- 新制（第五版）官方格式：PT/21 樂行童軍獎章、PT/22 貝登堡獎章、PT/69 考驗申請，含個人摘要、考驗項目、簽署及批核欄；學制可按成員設定：新制（第五版）、舊制（第四版）、舊制過渡新制。舊制表格（PT/21、PT/22、PT/69）按第四版官方格式由系統產生；過渡成員的舊制紀錄只作對照，須逐項核實後才加入新制
- 可編輯後列印，雙面列印符合總會要求

### 5. 用戶管理 - 角色及細緻權限
- 將成員改為管委：選單改角色 + 授權勾選
- **📥 批量開戶**：一次過為全團開戶，不用逐個填表
  - **方法一（最推薦）**：在 YMIS 匯出「自訂報表」PDF（欄位次序：童軍成員編號 → 中文姓名 → 電郵地址），APP 內直接上載（可輸入 PDF 密碼，瀏覽器內解密），預覽確認後一鍵開戶。教學見 [YMIS_EXPORT.md](YMIS_EXPORT.md)
  - **方法二**：下載 CSV 範本 → 填寫 → 上傳（一律開登入帳號；密碼留空＝預設 1234）
  - **方法三（備用）**：Google Sheets + Apps Script 直接寫入主資料表，見 [BULK_ONBOARD.md](BULK_ONBOARD.md)
  - 個人開戶：成員／支部領袖在登入頁「🆕 申請帳戶」→ 領袖在「✅ 審批中心」批准（團長／管理員／管委須由現任管理層在用戶管理直接開立）
  - **團長全團只可一位**：要換人請先把現任團長改為其他角色，再升新人；「升為團長」在已有團長時會反灰
  - **領袖免填 YMIS**：用電郵登入，系統自動編配內部編號（用戶名單不會顯示 L 開頭編號）
  - 批核後預設密碼 **1234**，首次登入必須更改（無法略過）
  - **忘記密碼**：成員可自助喺登入頁「🔑 忘記密碼」用登記電郵嘅一次性重設碼即場設新密碼（GS 5.2.3 起，見 [PASSWORD_RESET.md](PASSWORD_RESET.md)）；後端未升級或電郵發信未授權時，先喺用戶管理幫佢重設（重設權限有階級限制：副團長不可重設團長、團長不可重設管理員；管理員帳號不可由其他管理員重設。重設後該帳號即時解除登入鎖定、登出所有舊裝置，首次登入須改密碼）
- **⚙️權限按鈕**：
  - 領袖默認全部(*)
  - 成員默認無
  - 管委默認 L1（會員章）＋ OTHER（其他獎章）
  - 可按個別成員勾選可考核範圍：獎章、段章或項目；其他獎章逐個勾
  - 高層級可設定低層級可勾選範圍，除非團長/管理員更改
- 授權/收回勾選權限

### 6. 系統設定 - 私隱開關
- **允許成員互相查看進度**：預設關（只看自己，重私隱），團長可開啟（互相鼓勵，管委可按進度策劃活動）
- 在用戶管理頁 → 系統設定 → 開關
- 成員是否可看其他人進度由此控制

### 7. 審批申請
- 審批新帳號申請（YMIS/Email）

### 8. 資料庫
- 訓練綱要對照、訓練計劃、保護兒童 Safe from Harm 連結、佩戴指引、表格下載

### 9. 📖 ROVERBOOK 對接 - 成員自己手機的紀錄冊（GS 5.4.0 起）
- **定位不變**：本系統（ROVERBADGE）仍然係領袖統管＋一次過簽發的後台。**ROVERBOOK 只係多一個「成員自己擁有」的前端**（存喺佢自己部機），方便出外時隨時翻閱自己的紀錄冊。
- **團集會／考驗營「有參加就一次過簽」照舊用本系統**：「🏠 全團總覽 → 🚀 考驗營批量完成」或者「✅ 待批 → 批量批准」，**唔需要經 ROVERBOOK**。
- **個資不會上傳**：成員交上來時，系統會在收到的一刻剝走姓名（只保留成員編號）、電話、電郵、地址、出生日期、近照、簽名墨跡、緊急聯絡人 —— 這些**只留在成員自己的手機**，Google Sheet 不會有，你亦不會看到。對話框會顯示「已剝走個資欄位：N 項」。
- **成員自己簽 ≠ 已完成（重要）**：BOOK 交上嚟的每一項都只會放入「**紀錄冊待批**」，**未計入進度**。你逐項勾選／「全部確認」之後，才會寫入正式「進度追蹤」同產生核簽；按「拒絕」就唔會入帳。咁就唔會出現「成員自己喺 BOOK 簽完再錄入就扮完成」。
- **撤回／更正**：在「我的進度」取消某項完成 = 撤回，該項目即刻由成員的進度消失，成員下次取回時 ROVERBOOK 亦會移除（唔會再由核簽補回）。頒發錯日期／錯人：喺「一次過頒發」勾「更正已頒發的日期」或「撤回」，再按一次（會有確認對話框）。
- **打錯成員編號**：系統會直接拒絕（找不到成員），唔會產生無人跟進的紀錄；頒發更是整批拒絕，唔會半寫。
- **只加不減（但可以改）**：同一項目已有較後日期時，較舊的提交會顯示「較舊、未回寫（已保留）」而**不會**蓋走現有紀錄 —— 換機、還原舊備份、貼錯舊檔都唔會倒流行。你真係要改（例如當初打錯日期），確認時可以改日期，或者直接在「進度追蹤」改；已頒發的獎章永不改、不會重覆寫。
- 進入點：主畫面上方分頁「**📖 ROVERBOOK 對接**」（只對領袖顯示），三個子分頁：
  - **📥 接收進度**：成員在自己手機按「交給領袖」→ 複製文字或下載檔案 → 貼上／上載 → 放入「待批」→ 在下面表格勾選 → **✅ 確認所選（寫入進度）**／✅ 全部確認／❌ 拒絕所選。表格會標示「新項目／較後日期（會更新）／較舊（預設不改）／同一日」。
  - **🏅 一次過頒發**：一行一筆 `成員編號, 獎章, 日期`（例：`82-001, L1, 2026-11-01`）→ 一次過寫入「紀錄冊頒發」。已頒發的不會重覆寫、不會改期。
  - **📤 成員取回**：任何人按「取回我的進度」只拿回**自己**的進度／頒發／核簽 JSON（未確認的會另列「待領袖確認（未計入進度）」），貼回自己手機的 ROVERBOOK。
- 想睇全團邊個交了邊啲項目：「接收進度」下方有成員 × 項目的已完成清單（零個資，只有成員編號）＋待批清單。
- 試算表會自動多三張表：「**紀錄冊待批**」「**紀錄冊核簽**」「**紀錄冊頒發**」（按一次選單「🔧 初始化／更新」就會補建；只增不刪）。選單「📖 ROVERBOOK 對接狀態」可核對「待領袖確認 N 項」。
- 技術細節（格式版本、後端 action、ROVERBOOK 端要改乜）見 [ROVERBOOK_BRIDGE.md](ROVERBOOK_BRIDGE.md)。

## 最新版本公告、GS 更新與資料保全（必讀）

首頁、登入頁、登入後主頁頂部都會顯示「📢 最新版本公告」，附 Code.gs 下載、更新步驟及「🔄 重新檢查」按鈕。登入（或選定旅團）後會自動核對本旅團 Apps Script 的版本，結果分三種：

| 顯示 | 意思 | 你要做的事 |
| --- | --- | --- |
| ⚠️ GS 未更新 | 旅團 Apps Script 仍是舊版（或未回報版本） | 下載最新 Code.gs，貼上並在既有部署上選新版本，再按一次選單「🔗 旅系統 → 🔧 初始化／更新」（見下） |
| ⚠️ GS 已更新但未初始化 | 已貼上新版，但未按「🔧 初始化／更新」，畫面會寫「必須按一次選單「🔗 旅系統 → 🔧 初始化／更新」」 | 喺旅團試算表選單「🔗 旅系統 → 🔧 初始化／更新」按一次 |
| ✅ 已核對 | GS 已是最新版本，初始化已完成 | 無需操作 |

**更新步驟**

1. 按公告區的「⬇️ 下載 Code.gs」下載最新 `Code.gs`。
2. 打開旅團試算表 →「擴充功能」→「Apps Script」，全選刪除舊碼，貼上新 `Code.gs` 並儲存。
3. 「部署」→「管理部署作業」→ 編輯 ✏️ →「版本」選「**新版本**」→「部署」。**沿用原有 Web App 網址，不要另建新網址。** 只重新部署 Vercel 並不會更新 Apps Script。
4. 喺旅團試算表選單按「🔗 旅系統 → 🔧 初始化／更新（執行 initializeSheets）」一次（首次需按提示授權）。**呢個選單掣就係唯一嘅更新步驟**：重跑只會補建缺少的工作表、表頭欄與預設管理員，不會刪改任何既有帳號、進度、徽章、活動履歷、系統設定，亦不會更換 API Key。
5. 如需把 API Key 交管理員：選單「🔗 旅系統 → 🔑 顯示 API KEY（交 ADMIN）」。若上方出現「⚠️ 尚未完成初始化／更新（此 API Key 暫時未可用）」，請先按第 4 步嘅選單掣一次。
5. 回到本頁按「🔄 重新檢查」，出現綠色「✅ 已核對」即完成。

**資料保全規則（硬性規定）**

- 更新 Code.gs 或執行 `initializeSheets()`，**不會刪除、覆寫或重設**任何既有資料，包括：用戶帳號與密碼、成員名單、進度追蹤、其他獎章、活動履歷、待批、操作紀錄、登入 session（Tokens）、系統設定、API Key。
- `initializeSheets()` 只會做以下增補：
  - 建立缺少的工作表；
  - 在**空白**的表頭格補上欄位名（例如 `allowed_badges`、`force_change_password`、進度表的「確認者」「備註」）；
  - 若預設管理員列不存在，補回一列；
  - 補上缺少的系統設定列（例如 `allow_member_view_others`，預設 `false`）；
  - 若 API Key 不存在才會產生；已存在則保留不變；
  - 最後才記下「此版本初始化已完成」（前端據此顯示「已核對」）。
- 初始化**不會**刪列，也**不會**改寫既有的值。
- 密碼仍是預設值（`changeme`）的帳號，登入時會被要求強制改密（改在登入時判斷，不靠寫入資料）。
- 舊版殘留的代碼列（不屬於任何旅團成員）會保留，但不能用來登入。如要清理，請先備份試算表，再由技術人員手動執行 `removeSuperAdminRows()`。
- 任何需要刪除或改寫既有資料的升級，必須另行在 CHANGE_LOG 公告，並經用戶確認，**不可藏在 initializeSheets() 內**。

## 私隱聲明（個人資料收集、用途、儲存與保留）

本系統為非官方工具，處理個人資料時遵守香港《個人資料（私隱）條例》（第486章）的保障資料原則。以下為資料清單，方便你向成員／家長解釋：

- **收集乜嘢**：YMIS 編號、姓名、登記電郵、角色／職級、出席與進度紀錄、帳戶開關狀態，以及系統操作紀錄（審計 log，含登入失敗鎖定事件）。中央保留帳號只設於 Vercel 伺服器環境變數，**不寫入任何 Google Sheet**。
- **收集目的**：進度追蹤與統計、派發 badge、帳戶登入與安全（失敗鎖定、審計）、以電郵寄送一次性密碼重設碼。
- **儲喺邊**：全部個人資料只存於**你旅團自己嘅 Google Sheet**（Users、Applications、Tokens、操作紀錄、PasswordResets 等工作表）；中央 Vercel 伺服器只負責轉發請求與旅團清單，**不儲存個人資料**。第三方平台為 Google（試算表）與 Vercel（網站託管）；重設碼電郵由 Google Apps Script 的 MailApp 寄出。
- **保留期**：由各旅團自行管理。停用帳戶（deactivate）會保留紀錄但不能登入；徹底刪除（delete）即從試算表清走。密碼重設碼只存雜湊、15 分鐘有效、試錯 5 次後作廢，成功使用即刪除。
- **查閱／更正／刪除**：成員可隨時向旅團領袖或管理員要求查閱、更正或刪除其個人資料（依條例第 18／19 條）。
- **安全措施**：密碼以 PBKDF2-HMAC-SHA256（10,000 次迭代＋獨立 salt；GS 5.4.0 起由 120,000 調低，並改為每次登入只做一次 KDF、單行定位、舊雜湊登入時自動升級）儲存；同一帳號連續 5 次登入失敗會鎖定 15 分鐘；改密碼後其他裝置的登入 session 會被踢走；旅團間上下游同步以 HMAC 簽名驗證。
